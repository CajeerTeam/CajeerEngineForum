# Forum Edition 1.0.3 — SkiF4er ID Login

1. Deploy the **changed files** over the existing Forum Edition 1.0.2 source while maintaining the installed upstream CajeerEngine 2.1.0. Back up the app, configuration and database before deployment. Static assets are served directly from `public/forum-assets/` (no new frontend dependencies).
2. Register a **confidential** web client in Keycloak realm `skif4er` at `https://id.skif4er.ru/realms/skif4er`. Enable Authorization Code Flow and PKCE S256; disable Implicit/Direct grant. Add the precise HTTPS redirect URI `https://FORUM_HOST/auth/oidc/callback`. Configure the client secret server-side only.
3. Use the existing CajeerEngine OIDC configuration: `SKIF4ER_ID_ENABLED=true`, `SKIF4ER_ID_CLIENT_ID=...`, `SKIF4ER_ID_CLIENT_SECRET=...`, `APP_URL=https://FORUM_HOST`. Set strong application/OIDC encryption keys as documented in `docs/skif4er-id-production-1.9.3.md` and use trusted reverse-proxy HTTPS headers. Leave `SKIF4ER_ID_AUTO_PROVISION=false` for the controlled, pre-linked 1.0.3 rollout (new-user provisioning is scoped to 1.0.5).
4. Link a **specific existing CajeerEngine user** to the verified external issuer/subject using the existing privileged identity administration tools or documented `php bin/cajeer identity:link-user <user_uuid> <oidc_sub> --yes`. A matching email is deliberately insufficient. Existing forum threads and permissions remain on the local UUID. Account self-linking UX is planned for 1.0.4.
5. Visit `https://FORUM_HOST/forum/login` and select **Войти через SkiF4er ID**. Authorization redirects to the pinned realm. After successful token validation the server issues the same `ce_session` HttpOnly, Secure, SameSite=Strict cookie as the original CajeerEngine login, under `/api/v1`, and redirects to `/forum`. Optionally visit `/forum/login?return_to=%2Fforum%2Fthreads%2F...` to continue to a forum page. The server accepts only strictly validated relative forum URLs.
6. Verify `GET /api/v1/auth/me` succeeds for the new browser cookie and that allowed forum operations pass the existing server-side RBAC and ACL. Test invalid state, expired transaction, cancelled authorization, disabled/revoked account, missing link, and insufficient IdP MFA evidence. Errors return to `/forum/login` without a session. Verify `/auth/oidc/start` without `return_to` still returns to `/admin/` after successful authentication.

**Security:** No ID/access/refresh token is returned by a forum page or stored in JavaScript. The continuation cookie is signed against the one-time, random, browser-bound OIDC transaction and is cleared on callback; it cannot authorize a login. No database or OIDC SDK replacement is introduced. Local login and existing admin login are unaffected.

**Acceptance limitation:** The included test exercises the real controller flow with isolated HTTP/identity doubles and confirms security invariants; the existing `tools/oidc-regression.php` tests the cryptographic OIDC exchange with test keys. Real Keycloak authorization, TLS/proxy configuration, database state and browser session behavior must still be tested on staging with a registered client. This source patch does not include any client secrets or constitute a signed production certification.
