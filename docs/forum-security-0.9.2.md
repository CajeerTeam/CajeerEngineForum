# Forum Edition 0.9.2 — security operations

This release changes **executing runtime paths**, not only static checks. Do not bypass the `forum-required` CI gate.

## Production changes

- `Authorization` must be a single `Bearer ce_<64 hex digits>` credential. An invalid Authorization header, or present malformed `X-API-Token` header, never falls back to `ce_session`. Cookie sessions use the existing `X-CSRF-Token` check for state changes.
- API token revocation from `/api/v1/api-tokens/{id}` is owner-scoped. Revoking other users' sessions must use an explicitly authorized account-management workflow, not the personal token API.
- Non-domain runtime errors return a generic message with request ID. Operators correlate failures in protected runtime logs. Validation and database-unavailable statuses retain their pre-existing behavior.
- Webhook creation and URL changes require HTTPS on port 443 and a globally routable destination. DNS A/AAAA targets are checked against non-public ranges, and the chosen public address is pinned on every outbound request. DNS failure means validation fails closed. For local webhook development, use a public HTTPS testing endpoint rather than a loopback address.
- Webhook signing secrets are generated by the server from 256 random bits; caller-controlled secrets are rejected. On creation the signing secret is returned for one-time configuration; webhook listing and updates do not return it. Rotate an exposed secret by deleting/recreating the webhook.
- PostgreSQL/Redis Compose services now explicitly drop ambient Linux capabilities, enable `no-new-privileges`, remain only on the internal network, and receive only service-specific secrets. Their official entrypoints retain only required filesystem/UID transition capabilities.
- Bundled example Forum plugins have been validated for Forum Edition 0.9.x and now declare an explicit `<1.0.0` upper bound. Re-sign any changed extension manifests before installing them; do not disable compatibility checks for unverified third-party code.
- Extension trust roots must contain regular non-symlink public key files that are not group-/world-writable. Private extension keys remain operator-managed. Validate existing ownership and permissions before deploying.
- Uploads of images larger than 16 million pixels are rejected before image processing. Existing originals are unchanged.

## Test commands

```bash
php tools/forum-security-hardening-regression.php
php tools/security-regression.php
python tools/forum-tests/run.py --suite api --report storage/tmp/forum-ci/network
vendor/bin/phpunit tests/Security tests/Forum
```

The network suite uses an isolated database and verifies rejected forged CSRF, invalid bearer fallback, cross-account token revocation, content rendering, private attachments and ACP permissions. The first two PHP commands can run without Composer.

## Release gate

Tagged releases remain subject to the signed candidate, dependency audit, CI evidence aggregation and publisher revalidation introduced in 0.9.1. Review the full CI results and exercise container/host operations before promotion. No third-party penetration testing or live production acceptance was performed in this source-only change.
