# Platform Security & Privacy — Forum Edition 1.4.7

Upgrade from 1.4.6 after a verified backup. Stop old PHP workers, queue workers and scheduler before replacing files; restart after deployment. No schema migration or dependency change. Verify the existing signed release/CI/staging gates before publication.

## Abuse controls

`RATE_LIMIT_DRIVER=file` retains the existing on-disk fixed-window counters for a single shared filesystem. `RATE_LIMIT_DRIVER=redis` uses the existing `REDIS_*` settings and unique `FORUM_REDIS_NAMESPACE` for atomic counters with TTL. Redis admission fails closed on connection, state or command failure, never silently falling back to independent local counters. Use a dedicated or properly capacity-managed Redis with `maxmemory-policy noeviction`; do not flush limiter keys. Switching drivers resets active windows. A load-balanced installation needs shared Redis, not independent local counters. Configure trusted reverse proxies at the gateway/application boundary; the limiter never directly trusts forwarding headers.

HTTP buckets normalize IPv4-mapped IPv6 and IPv6 /64. The login endpoint additionally applies an account/network pair limit (`RATE_LIMIT_LOGIN_PAIR`, default 8) and account-wide limit (`RATE_LIMIT_LOGIN_ACCOUNT`, default 30) over 600 seconds before password hashing. Both count attempts, including successful ones. They do not permanently lock accounts; a targeted attacker can temporarily exhaust an account's window. Tune thresholds for shared networks; keep existing IP, registration, forum publishing and AI quotas enabled. Retry-After is returned on refusal.

## Secrets

For each supported name, either keep its direct environment value or set `<NAME>_FILE` to an absolute protected regular file, not both. Names: `INTEGRATIONS_KEY`, `INTEGRATIONS_PREVIOUS_KEYS`, `SKIF4ER_ID_TRANSACTION_KEY`, `SKIF4ER_ID_TRANSACTION_PREVIOUS_KEYS`, `SKIF4ER_ID_CLIENT_SECRET`, `OPENAI_API_KEY`, `DB_PASSWORD`, `REDIS_PASSWORD`, `FORUM_SMTP_PASSWORD`, `OBSERVABILITY_METRICS_TOKEN`, `OBSERVABILITY_OTLP_TOKEN`. Files must be accessible to the runtime user, max 16 KiB, mode 0600 or 0440 (no world access or group writes), single line with optional trailing newline. Direct symlinks are rejected. Keep files outside the document root, in operator-controlled directories. Empty or unreadable files and conflicting sources fail closed; diagnostic output includes source type and status only. `APP_KEY` provisioning remains unchanged. Existing encrypted stored credentials and `keys:status` / `keys:rekey --yes` continue to work; preserve previous keys until an offline rekey and verified backup finish. Do not use install/fix/restore commands to rewrite externally provisioned credentials without reviewing their environment handling; mount secrets again after restoring.

## Audit and privacy

Both file and SQL audit writers redact structured credential fields, common secret formats and raw email addresses, bound nested metadata, and preserve IDs and decision history. This is defense in depth, not a guarantee of detecting arbitrary secrets in free text; never pass raw user content or credentials to audit calls. New SQL audit rows retain only an IPv4 /24 or IPv6 /48 network hint, not raw User-Agent. The hourly `security.cleanup` task removes expired file counters and clears old SQL audit network/device fields in batches of up to 500 (default 30 days, configurable 1–90 via `AUDIT_NETWORK_RETENTION_DAYS`). Account erasure clears those fields for the closed account inside its existing transaction. Historical audit contexts are redacted on the affected audit read paths but are not rewritten on disk; review older logs/backups under the site's retention policy. File audit uses owner-private writes and bounded recent reads; rotate/archive it with the existing operational log retention policy. This is not a cryptographically immutable audit ledger. Support archives now export only bounded audit event summaries, aggregate runtime telemetry and environment variable names, not raw historical logs or dotenv values.

## Operations

`php bin/cajeer security:doctor` reports configuration and credential source health. `php bin/cajeer ops:report` and System ACP show security probes, recent rejection/denial counters, and cleanup scheduler state. `php bin/cajeer scheduler:run` executes due cleanup. Metrics contain operation categories and outcomes, not account or IP identifiers. Test Redis unavailable behavior and restore, account limits, audit permissions, data export/erasure and actual DB maintenance in staging. Local offline regression: `php tools/platform-security-regression.php`; CI: `php tools/platform-security-regression.php --database --redis`.
