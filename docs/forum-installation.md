# Установка и первый запуск Forum Edition 1.6.0

[Документация](README.md) / Установка

## 1. Выберите способ поставки

| Формат | Назначение |
| --- | --- |
| Исходники (`source`) | Разработка, аудит, локальная сборка; зависимости устанавливаются отдельно |
| Полный подписанный `dist` | Установка после проверки подписи, контрольной суммы, идентичности и релизной приёмки |
| Архив изменённых файлов | Наложение на соответствующий исходный checkout; не установщик и не пакет `update:apply` |

Получайте релизы только из [репозитория Forum Edition](https://github.com/CajeerTeam/CajeerEngineForum/releases). Не используйте пакет обычной CMS CajeerEngine. До сборки сверяйте идентичность исходников: [проверка VERSION и версии редакции](releases/1.6.0.md#проверка-идентичности-сборки).

## 2. Подготовьте окружение

- PHP `>=8.4.1 <9.0`; Composer 2; расширения `json`, `mbstring`, `pdo`, `phar`, `sodium`, `fileinfo` и PDO-драйвер БД согласно `composer.json`. Для сетевых интеграций и операций с архивами проверьте дополнительные требования выбранного профиля.
- PostgreSQL 17/18 — основной профиль. SQLite 3.40+ — локальная разработка и демо. MySQL 8.4+/MariaDB 10.11+ требуют отдельных проверок; автономное восстановление на них не поддерживается.
- Для production выделите отдельные каталог сайта, БД, пользователя БД, PHP-FPM pool, TLS и защищённые секреты. Node.js нужен при пересборке frontend, а не для обслуживания уже собранных assets полного dist.

## 3. Локальная установка из исходников

```bash
composer install --no-interaction
php bin/cajeer install --sqlite --interactive
php -S 127.0.0.1:8080 -t public
```

Перейдите на <http://127.0.0.1:8080/> и `/admin/`. Не открывайте встроенный сервер наружу. Если исходное дерево не проходит проверки версии, используйте исправленный проверенный checkout, а не отключайте валидацию.

## 4. Серверная установка

После допуска проверенного dist и подготовки БД запустите установщик под подходящим сервисным пользователем:

```bash
php bin/cajeer install --interactive
```

Выберите PostgreSQL и укажите параметры отдельной базы. Альтернативно web installer открывается по `/install` после создания одноразового токена:

```bash
php bin/cajeer install:web-token
```

Не передавайте реальные пароли в открытых командах, CI-логах или скриншотах. После установки проверьте наличие `storage/app/installed.lock` и ограничение повторного запуска установщика.

Пример важных настроек `.env` (домен замените на собственный):

```dotenv
APP_ENV=production
APP_DEBUG=false
APP_URL=https://forum.example.org
FORUM_REGISTRATION=false
UPDATE_AUTO_APPLY_ENABLED=false
UPDATE_ACP_POLICY_ENABLED=false
```

Закрытая регистрация — безопасная стартовая рекомендация. Перед публичной регистрацией настройте SMTP, подтверждение email, антиспам и роли. Не переносите демонстрационные секреты из `.env.example`.

### Nginx и PHP-FPM

Document root должен указывать только на `public/`. Генератор конфигурации можно предварительно просмотреть:

```bash
php bin/cajeer nginx:config --domain=forum.example.org
```

Адаптируйте сокет PHP-FPM, TLS, права и ограничения доступа к скрытым файлам под сервер. `.env`, runtime, приватные вложения и ключи не должны быть доступны напрямую из сети. Для автономного обновления нужен дополнительный независимый maintenance gate; см. [управление службами](forum-safe-deployment-1.5.7.md).

## 5. Фоновые службы и первичная проверка

Сначала просмотрите предлагаемые systemd units и проверьте права пользователей:

```bash
php bin/cajeer scheduler:install --print
php bin/cajeer worker:install --print
php bin/cajeer doctor --json
php bin/cajeer migrate:status
php bin/cajeer admin:assets --check --json
php bin/cajeer post-install:report
```

Затем установите и запустите проверенные службы через оператора ОС. Не включайте произвольные привилегии web-пользователю. Для автономного режима используется отдельный процесс, а не PHP-FPM.

Перед открытием сайта проверьте `/health/live`, `/health/ready`, вход в ACP, тестовую тему и ответ, поиск, права закрытых разделов, очередь и планировщик. Создайте резервную копию и отдельно проверьте её восстановление на изолированной среде:

```bash
php bin/cajeer backup:create
```

Наличие файла копии не является доказательством восстановления. Сохраните секрет восстановления отдельно. Для публичной эксплуатации требуется собственная staging-проверка, а для выпуска — полный внешний цикл приёмки.
