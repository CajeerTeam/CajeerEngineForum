# Unified Update Center 1.5.9

The published ACP at `/admin/#/updates` controls the existing updater. No package is executed by PHP-FPM. GitHub catalog, verified stage, compatibility, pending requests, download progress, autonomous operator heartbeat, active transaction/service phase, last report, backup, rollback and update history are shown together. A rollback request must identify the exact committed transaction, not just a version. Backup and rollback remain separate explicit approvals. Existing integrity, backup, recovery and service lifecycle checks remain authoritative.

## Delegation (optional, default off)

Set `UPDATE_ACP_POLICY_ENABLED=true` in the host environment seen by both PHP-FPM and the dedicated update operator. This explicitly delegates editing of non-secret update policies to full ACP administrators, including the power to authorize signed updates within host restrictions. Do not enable delegation if web-tier administrators should not have that responsibility. A compromise of the web tier can affect delegated policy; never delegate trust keys, service privileges, arbitrary paths, executables, tokens or backup credentials. Leave delegation disabled for hosts requiring exclusively host-owned policy.

Retain the existing host requirements (`UPDATE_OPERATOR_ENABLED`, `UPDATE_WEB_UPGRADE_ENABLED`, trusted key, backup key, service policy and independent supervisor). `UPDATE_AUTO_APPLY_ENABLED=true` is a host prerequisite, not a setting the browser can enable on its own. With that host flag false, no ACP policy can enable autonomous apply. `UPDATE_CHANNEL` is the maximum allowed channel (stable only, rc plus stable, beta plus stable, or dev including all); `UPDATE_SEQUENTIAL=true` cannot be weakened; host `UPDATE_BLOCKED_VERSIONS` are unioned with ACP blocks. Host automatic-discovery and operator flags are not editable. Other policy values (including mode and schedule) are explicitly delegated when enabled. To revoke delegation set `UPDATE_ACP_POLICY_ENABLED=false` in both environments; host settings resume, persisted ACP policy is ignored. To emergency-stop future autonomous work also turn off `UPDATE_AUTO_APPLY_ENABLED` and stop the operator timer, not a running recovery process. Revocation does not interrupt an operation already admitted.

Use the existing shared update-requests directory provisioning: directory `storage/app/update-requests` must be setgid (02770) with shared `cajeer-update-requests` group and both web and operator users authorized. Do not make it world writable. `center-policy.json` is atomically persisted (0640), and `center-policy.lock` (0660) serializes administrator writes against the operator poll. The shared group must be inherited by both files. The state is outside release and backup replacement. With existing manual operator directory provisioning no new database migration is needed. Restart PHP-FPM and let the operator start a fresh invocation after changing host configuration.

## ACP workflow

Open the policy editor, choose mode, allowed channel, sequence, automatic apply flag, IANA timezone, days 1–7, start/end time (both empty for unrestricted hours), optional UTC deferral `YYYY-MM-DDTHH:mm:ssZ` and comma-separated versions. Save, confirm, then complete existing session-bound reauthentication if required. The operator reloads persisted settings after acquiring a shared policy lease. A save racing an active operator or a stale revision/host baseline is rejected with HTTP 409; reopen the editor after the operator finishes. The browser suspends polling while the editor is open. Reset restores host settings while retaining the revision and recent 20 policy changes. Reset can re-enable host-configured modes; review host settings first. If a saved policy becomes incompatible with the host, update operations fail closed until the policy is corrected or reset. Malformed persisted state requires host intervention. Never remove an active recovery journal to bypass a failure.

Manual installation retains explicit confirmation; changing policy does not bypass signed-package verification or immediately install anything. Pending operations are checked against effective policy during operator admission. A running operation cannot be cancelled by a policy change. An active Nginx maintenance gate can make the ACP unavailable, so manual reopening may require the CLI after recovery is complete.

## Acceptance

`php tools/update-center-policy-regression.php` exercises the actual policy store, config loading, host ceilings, revisions, blocking, exact rollback request and corrupt-state handling. `python tools/update-center-browser-regression.py --browser chromium` (or firefox) exercises the published static ACP with controlled API responses; it is not a live PHP/SQL E2E. Run strict API lint, complete CI and physical signed update/rollback qualification before publication. The version remains production-stable-gated.
